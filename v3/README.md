# MedQT 3 (в разработке)

Новая версия: сервер на Python (FastAPI) + интерфейс на React в собственном окне (WebView2).
Старое приложение 2.9.x в корне репозитория не затрагивается.

## Первый запуск

```
python -m venv .venv
.venv\Scripts\pip install fastapi==0.115.* uvicorn==0.32.* pywebview==5.* reportlab==4.* pypdfium2==4.* pywin32==308 pillow==11.*
cd frontend && npm install && npm run build && cd ..
```

Перенос данных из старой базы (старый файл открывается только на чтение):

```
cd backend
..\.venv\Scripts\python -m medqt3.importer ..\..\patients.db
```

Новая база создаётся в `v3/data/medqt.db` (в git не попадает). Повторный перенос: добавить `--force`.

Справочники, которые врач дополняла в 2.9 (диагнозы, обследования, обоснование лечения, адреса), добавляются
из папки `data` программы 2.9: `--dicts путь\к\MedQT-2.9\data`. Ничего не удаляется, только добавляются новые значения.

**Переход на ноутбуке** (один раз): закрыть 2.9, взять её `patients.db` и папку `data`, выполнить перенос
с `--db ...\MedQT\data\medqt.db --dicts ...\data`, затем запустить `MedQT.exe`. Для русских букв в консоли —
`set PYTHONIOENCODING=utf-8`.

Тестовый пациент (вымышленный, история № ТЕСТ: первичный осмотр, 8 дневников и протокол операции, ничего не напечатано, хватает на два листа):
`..\.venv\Scripts\python -m medqt3.demo` в `backend`. Повторный запуск удаляет прежнего тестового пациента
со всем, что для него печаталось, и создаёт заново — проверку печати можно начинать с чистого листа.

Для проверки печати на настоящих историях: `--as-unprinted` — все записи переносятся как ненапечатанные
(без отметок и позиций 2.9), чтобы любую историю можно было напечатать в новой версии с первого листа.
Только для проверки, не для настоящего переноса.

## Запуск

- В своём окне: `Запуск MedQT 3.bat`.
- Для разработки: `..\.venv\Scripts\python -m medqt3.serve` в `backend`, затем `npm run dev` в `frontend` (http://localhost:5173).

## Сборка для ноутбука врача

```
.venv\Scripts\python build.py
```

Получится портативная папка `dist\MedQT\` (`MedQT.exe` + `_internal\`) и архив `dist\MedQT-<версия>-win.zip` (~31 МБ).
Перед упаковкой сборка сама запускает `MedQT.exe --self-test`: интерфейс, справочники, PDF, предпросмотр,
принтеры, резервная копия — если что-то не так, архив не делается.

- **Установка:** распаковать папку `MedQT` куда угодно с правом записи (например, `D:\MedQT`, не в Program Files),
  ярлык на `MedQT.exe` — на рабочий стол. Интернет и Python не нужны; WebView2 в Windows 10/11 уже есть.
- **Данные:** `data\` рядом с `MedQT.exe` — база `medqt.db`, копии `data\backups\`, журнал ошибок `medqt.log`.
  В сборке папки `data` нет никогда.
- **Обновление:** закрыть программу, скопировать новую папку `MedQT` поверх старой. `data\` не трогать.
- Вторую копию программы открыть нельзя — две сразу печатали бы на одни и те же места листа.

## Резервные копии

Справочники → «Резервные копии». Копия делается сама при запуске и раз в сутки, пока программа открыта,
кнопкой «Сделать копию сейчас» и перед каждым восстановлением. Каждая проверяется (`PRAGMA quick_check`)
и хранится одним файлом. Хранятся 14 последних автоматических и по одной за каждый из 12 месяцев;
копии «вручную» не удаляются. Можно указать вторую папку (флешка, другой диск) — каждая копия дублируется туда.
Восстановление сначала сохраняет текущее состояние, потом возвращает базу к выбранной копии.

## Устройство

- `backend/medqt3/db.py` — схема SQLite: UUID, `created_at`/`updated_at`, мягкое удаление (готово к синхронизации с телефоном).
- `backend/medqt3/importer.py` — перенос из 2.9.x без потерь: структурированные формы в `data_json`, печатный HTML в `html_legacy`, остальные старые колонки в `legacy_json`, старые id в `legacy_id`. Нераспознанные даты сохраняются как набраны (`unparsed_date`).
- `backend/medqt3/api.py` — API; отдаёт собранный интерфейс из `frontend/dist`.
- `backend/medqt3/desktop.py` — сервер на 127.0.0.1 + окно; одна копия программы; без консоли пишет ошибки в `data/medqt.log`.
- `backend/medqt3/paths.py` — где лежат данные и интерфейс (из исходников и в собранной папке).
- `backend/medqt3/backups.py` — резервные копии; `selftest.py` — самопроверка собранной программы.
- `backend/medqt3/diaries.py` — дневники и обход (вчерашние Vis/ВГД/АД/пульс подставляются, но подсвечены «как вчера», и при сохранении неизменённых программа переспрашивает).
- `backend/medqt3/printlayout.py` — PDF листа дневников в стиле «В стиле программы» (Onest, только чёрный — ч/б лазерный принтер): шапка листа (отделение + пациент) и «лист N» только на новом листе, дата каждой записи в рамке; начало печати с заданного мм.
- `backend/medqt3/fonts/` — Onest Regular/SemiBold/Bold (OFL, см. `OFL.txt`), статические начертания из вариативного шрифта Google Fonts.
- `backend/medqt3/printjobs.py` — задания печати. «На лист истории»: новые записи под последней, отмеченные напечатанные — точно на своё сохранённое место (`print_positions`); «Копия подряд» ничего не отмечает. Записи отмечаются и места сохраняются только после «ровно ли вышло → да».
- `backend/medqt3/admission.py` — новое поступление: поиск пациента (повторные поступления), номер истории — следующий после наибольшего, справочники (`medqt3/dictdata/*.json`, перенесены из `data/` 2.9).
- `backend/medqt3/exam.py` — первичный осмотр в формате 2.9 (`primary_exam_v1`): нормы, варианты, правило «глазное дно не просматривается», печатный HTML собирается так же, как в 2.9.
- `backend/medqt3/exams.py` — сохранение осмотра (обновляет диагнозы истории, как 2.9) и шаблоны осмотров (без измерений и диагнозов пациента).
- `backend/medqt3/htmlprint.py` — печать первичных осмотров 2.9 из их сохранённого HTML (как печатала 2.9): текст, дроби Vis/ВГД, таблица местного статуса, стили `.title` и размер шрифта.
- `backend/medqt3/winprint.py` — печать на принтер Windows в масштабе 100% с учётом непечатаемого поля принтера.

Тесты: `cd backend && ..\.venv\Scripts\python -m pytest -q tests`.
Зависимости печати: `reportlab==4.*`, `pypdfium2==4.*`, `pywin32==308`, `pillow==11.*` (плюс `httpx`, `pytest` для тестов).
- `backend/medqt3/dicts.py` — справочники (диагнозы, сопутствующие, обследования, обоснование лечения, адреса): исходные списки из 2.9, правки врача хранятся в базе и попадают в копии.
- `backend/medqt3/records.py` — «Новая запись»: протокол операции (поля 2.9) с шаблонами операций и текстовые записи (предоперационный эпикриз, консилиум, продление листка, посмертный эпикриз, своя); печатаются на лист дневников.
- `backend/medqt3/stats.py` — статистика: пять графиков 2.9 (госпитализации, выписки, средний койко-день, диагнозы по группам архива, исходы) за выбранный период.
- `backend/medqt3/rxprint.py` — печать листа назначений (A4, по разделам, с датами назначения и отмены).
- `backend/medqt3/report.py`, `reportdoc.py` — отчёт отделения как сдаёт отделение: основные показатели, «Структура пролеченных больных» по нозологиям, операции, исходы, как госпитализированы; выгрузка в Word (.docx пишется без сторонних библиотек). Группа для отчёта выбирается при выписке (подсказка по диагнозу), вид операции и срочность — в протоколе, как поступил — при поступлении; сёла для «сельских жителей» — в справочнике адресов; число коек и план койко-дней — в настройках.
- `frontend/src` — интерфейс в стиле «Мягкий».
